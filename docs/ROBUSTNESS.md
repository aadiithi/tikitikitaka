# Robustness Evaluation Summary (deliverable #4)

Generated by `scripts/evaluate_robustness.py` and `scripts/make_report.py`.
Paste the outputs below after a run — do not type numbers by hand.

## Protocol

Two models are compared. **One variable differs between them:** whether the
training features were extracted from pristine images or from randomly damaged
ones. Same backbone, same head architecture, same seed, same source images,
same hyperparameters.

| | clean | robust |
|---|---|---|
| training features | 1 pristine view per image | 4 independently damaged views per image |
| damage policy | none | `TrainDamagePolicy` — see below |
| backbone | frozen CLIP ViT-L/14 | frozen CLIP ViT-L/14 |
| head | 768→256→1 MLP | 768→256→1 MLP |

Both models are evaluated on **identical corrupted images**, encoded once per
condition and scored by both — so no difference can come from the corruption
being applied differently. Each model uses **its own threshold**, fixed on
validation data and never re-tuned per condition.

## The three grids

**1. Specified transforms** — the ones named in the problem statement. These are
what we are asked to be robust to.

| family | severities |
|---|---|
| JPEG compression | q90, q70, q50, q30 |
| Gaussian blur | σ 0.5, 1.0, 2.0 |
| Rescale (down then back up) | 0.50×, 0.25× |
| Gaussian noise | σ 0.02, 0.05, 0.10 |
| Colour jitter | ±20% brightness / contrast / saturation |
| Centre crop | keep 80% |

**2. Held-out corruptions** — *never used in training.* This is the honest
generalisation number.

| condition | why it is a different kind of damage |
|---|---|
| WebP q80 / q50 | no 8×8 block grid — tests whether the model learned "JPEG artefacts" or something about the image |
| Sharpen ×1.0 | *amplifies* high frequencies instead of removing them — the opposite failure mode from blur |
| Rotate 2° | resamples every pixel off-grid, destroying pixel-aligned periodic artefacts without visible change |
| Screen re-capture | downscale + blur + contrast + JPEG, i.e. a screenshot |

**3. Compound corruptions** — two operations in sequence, because nobody sees a
single-corruption image in the wild.

`rescale0.5+jpeg50` · `crop80+jpeg30` · `blur1.0+jpeg70` · `recapture+jpeg50`

## Training damage policy

Deliberately *not* the eval grid:

| operation | training range | evaluated at |
|---|---|---|
| JPEG quality | uniform [25, 95] | {90, 70, 50, 30} |
| blur σ | uniform [0.3, 2.5] | {0.5, 1.0, 2.0} |
| rescale factor | uniform [0.20, 0.85] | {0.50, 0.25} |
| noise σ | uniform [0.01, 0.12] | {0.02, 0.05, 0.10} |
| colour strength | uniform [0.05, 0.30] | 0.20 |
| crop keep | uniform [0.65, 0.95], random position | 0.80, centred |

25% of training images stay clean; 35% of damaged ones get a chain of two
operations. Continuous ranges mean the head cannot memorise four specific
quantisation tables, so the reported numbers are not "trained on the test set"
in disguise.

## How to read this

- **Clean AUC going down slightly for the robust model is expected**, and is the
  cost of corruption training. Report it; do not hide it.
- **The held-out column is the claim.** Improvement on the specified transforms
  could in principle be memorisation of those transforms. Improvement on
  corruptions never trained on cannot be.
- **Watch `separation`, not only accuracy.** A model whose two score
  distributions collapse toward each other under damage has become *uncertain*;
  one whose distributions cross has become *wrong*. The fixes are different.
- **AUC differences below about 0.01 on a 2–3k test set are noise.** Use
  `eval.metrics.bootstrap_ci` before claiming a small gap is real.
